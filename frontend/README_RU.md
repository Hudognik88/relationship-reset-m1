# Публичный фронтенд на TypeScript

## Разработка

Node.js 24 используется в CI. Зависимость сборки — закреплённый TypeScript 5.9.3; runtime-зависимостей нет. Компилятор выбран для совместимости с существующими браузерными скриптами, а не как утверждение о новейшей версии TypeScript.

```sh
npm ci --ignore-scripts
npm run build
npm test
npm run build:check
```

Редактируйте исходники в `frontend/`, затем запускайте сборку и включайте сгенерированные файлы в коммит. CI повторяет строгую компиляцию и отвергает несовпадение исходников и результатов.

| Источник | Результат |
| --- | --- |
| `landing/content.ts`, `landing/page.ts`, `styles/site.css` | `pilot.html` |
| `browser/app.ts` | `app.js` |
| `browser/reset-logic.ts`, `browser/types.ts` | `reset-logic.js` и общие типы для проверки |
| `templates/success.html` + `browser/success.ts` | `success.html` с встроенным скриптом |
| `templates/privacy.html` + `browser/privacy.ts` | `privacy.html` с встроенным скриптом |
| `templates/index.html`, `templates/terms.html` + общие стили | `index.html`, `terms.html` |

Шаблоны HTML не требуют притворяться TypeScript: типы защищают данные, поведение и сборку. Лендинг собирается заранее и не требует гидратации. FAQ работает через нативный `details`, переходы — обычными ссылками. Это сохраняет скорость и существующий ограниченный способ публикации.

## Публикация

Изменения попадают PR в `m1-first-payment-20260925`. После успешных проверок push этой ветки запускает существующий Beget CI: сборка → проверки → упаковка → последовательная публикация тестовой части и `pilot.html` → проверка HTTPS и точного SHA256 страницы. Новые секреты, ручная загрузка файлов и вход в Beget для обычного изменения фронтенда не нужны.

На публичном `pilot.html` сохранены ограничения: только информация и mailto/Telegram; никаких скриптов, форм, внешних ресурсов или оплаты. Не добавляйте клиентский бандл сюда без отдельного изменения архитектуры публикации. Корневая страница с бесплатной анкетой остаётся тестовой, с предупреждением и отключёнными обращениями. Работа анкеты локальна и предназначена для вымышленных данных в этом окружении.

Kotlin backend, служебные `/owner/` и `/rehearsal/`, платёжные настройки и серверные секреты этой сборкой не меняются. PWA и клиентский кабинет — отдельный этап после проверки основного сценария; service worker сейчас не устанавливается.

## Проверки

`npm test` проверяет защитные ветки локальной анкеты и контракт сгенерированных страниц. Дополнительные VM-тесты проверяют сохранённые данные и копирование/удаление без браузерных сетевых запросов. Python-тесты публикации сохраняют проверку допустимого содержимого, целостности архива, атомарной замены и отката. CI отдельно повторяет receiver-тесты на Python 3.10, который используется на Beget.

Визуальная проверка и тест реального пути по опубликованному HTTPS выполняются отдельно от компиляции. Успешная типизация не доказывает удобство страницы или рост продаж. Исследование и план проверки спроса: `docs/FRONTEND_DESIGN_RESEARCH_RU.md`.
