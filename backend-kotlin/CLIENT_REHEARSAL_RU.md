# Тестовый клиентский кабинет

Адрес: https://api-staging.poslessory.ru/rehearsal/

Это закрытая репетиция услуги «После ссоры». Используются только вымышленные
ситуации. Приглашение одноразовое и действует один час; сеанс в браузере —
24 часа. Вход с нового устройства, восстановление после выхода и полноценный
клиентский аккаунт ещё не реализованы. Этот режим не предназначен для продажи
семидневного сопровождения.

## Путь участника

1. Ввести выданный владельцем одноразовый код. Код не нужно добавлять в URL.
2. Пройти проверку возраста и безопасности до ввода свободного текста.
3. Заполнить вымышленную ситуацию и подтвердить тестовый характер данных.
4. Сохранить анкету. Повторная отправка того же запроса не создаёт дубль.
5. Вернуться в тот же браузер и нажать «Обновить», чтобы увидеть опубликованный
   человеком разбор. До публикации отображается ожидание.

В каждом сеансе доступна только своя анкета. Можно удалить её и разбор из
рабочей базы или выйти из кабинета. Удаление не удаляет уже созданные резервные
копии; сейчас они хранятся на VPS. После выхода нужен новый код и начинается
новый тестовый сеанс.

## Работа владельца

Команды выполняются в терминале тестового VPS от root. Управляющий скрипт
читает операторский токен из закрытого файла; токен не нужно копировать в
браузер, GitHub, командную строку или переписку.

После контролируемого обновления скрипт установлен в
`/opt/relationship-reset-kotlin-deployer/client-admin-vps.py`.

```sh
# Создать одноразовое приглашение. Код появится только в терминале.
python3 /opt/relationship-reset-kotlin-deployer/client-admin-vps.py invite

# Посмотреть идентификаторы последних тестовых анкет.
python3 /opt/relationship-reset-kotlin-deployer/client-admin-vps.py list

# Прочитать выбранную анкету; замените CASE_ID её идентификатором.
python3 /opt/relationship-reset-kotlin-deployer/client-admin-vps.py show CASE_ID
```

Код приглашения передавайте только конкретному участнику репетиции. Не
публикуйте его в канале и не добавляйте в документы проекта.

После прочтения анкеты подготовьте вымышленный разбор в обычном UTF-8-файле
в закрытом каталоге на VPS, например `/root/rr-review.txt`. Файл должен
принадлежать root, иметь права `600` и содержать не более 4000 символов.
Проверьте содержание перед публикацией. Автоматической генерации или
автоматического утверждения разбора здесь нет.

```sh
chmod 600 /root/rr-review.txt
python3 /opt/relationship-reset-kotlin-deployer/client-admin-vps.py \
  publish CASE_ID /root/rr-review.txt --reviewed
```

## Установка и проверка

Миграция `002_client_rehearsal` создаёт четыре отдельные таблицы для приглашений,
сеансов, клиентских анкет и опубликованных разборов. Схема `001_initial` и старый
операторский API сохраняются. Миграция запускается только явной командой
`migrate-client`, а не при обращении к сайту или старте API.

Контролируемое обновление существующего VPS выполняет
`scripts/upgrade-client-vps.py REVIEWED_FULL_SHA`. Перед изменениями он проверяет
точный коммит и CI, останавливает таймер и сохраняет резервную копию. После
миграции проверяются старый API, новый клиентский сценарий и восстановление
копии. Изменения схемы требуют этого отдельного шага; обычный автодеплой не
применяет новые миграции.

`scripts/smoke-client-vps.py --release SHA --secret-dir PATH` проверяет через
настоящий HTTPS два независимых сеанса, одноразовость приглашений, CSRF,
серверные ограничения анкеты, повторную отправку, публикацию разбора,
удаление и выход. Все создаваемые им данные вымышленные.
