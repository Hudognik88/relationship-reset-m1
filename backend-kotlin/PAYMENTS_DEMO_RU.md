# Демо-оплата Prodamus: границы и запуск

Эта версия добавляет серверный заказ и обработку подписанного уведомления.
В опубликованном Compose оплата **отключена**: отсутствуют платёжный секрет
и настройки его монтирования. Рабочие платежи и публичная продажа не включаются.
Существующая репетиция по приглашению продолжает работать без оплаты.

## Что проверяет реализация

Клиент сохраняет вымышленную анкету и личный ключ кабинета. Заказ привязывается
к постоянному владельцу кабинета и конкретной анкете. Сервер задаёт продукт
`pilot_7d`, сумму 99000 копеек, RUB и режим demo. Сумма из браузера не принимается.
Повтор запроса с тем же UUID возвращает тот же заказ; другой UUID для той же
анкеты сохраняется как его псевдоним. Использовать UUID для другой анкеты нельзя.

Подписанная ссылка указывает только на `https://relationshipreset.payform.ru/`
и содержит `demo_mode=1`. Контакты, содержание анкеты, ключ кабинета и cookie
в неё не попадают. Открытие ссылки производится клиентом явно.

Возврат со страницы оплаты не меняет заказ. Только серверное уведомление
с корректным `Sign`, ожидаемыми доменом, суммой, валютой, номером заказа,
статусом `success` и явным `demo_mode=1` создаёт демо-доступ на семь дней.
Запись уведомления, изменение заказа и выдача доступа — одна транзакция.
Повторная доставка не продлевает срок и не выдаёт второй доступ.

Удалённая анкета не заменяется новой в старом заказе. Успешное уведомление
после удаления получает состояние `review_required`, без выдачи доступа.
Удаление после выдачи делает доступ неактивным; платёжный журнал сохраняется.
Сервер не возвращает ссылку на оплату заказа удалённой анкеты.
Демо-доступ пока не ограничивает существующую бесплатную репетицию.

## API

| Метод и путь | Условия и результат |
| --- | --- |
| `GET /client/orders` | Cookie клиента; собственный заказ и демо-доступ. При отключённой оплате `enabled:false`, остальные поля null. |
| `POST /client/orders` | Cookie, точный Origin, CSRF; JSON `synthetic:true`, `product:"pilot_7d"`, `client_request_id` UUID, `case_id` 32 hex. При отключённой оплате 503. |
| `POST /payments/prodamus/webhook` | HTTPS, без query; подпись в единственном заголовке `Sign`; URL-encoded или multipart form, до 64 KiB. При отключённой оплате 503. |

В уведомлении `order_num` — наш идентификатор `rrstg_…`, а `order_id` —
идентификатор Prodamus. JSON-уведомления и подпись в теле не поддерживаются.
Успешный ответ 200 выдаётся после фиксации транзакции. Неподписанное,
несовпадающее или неявно тестовое уведомление не выдаёт доступ.
Сырой webhook, контакты плательщика и подпись не сохраняются.

## Контролируемое обновление VPS

Миграция `004_client_payments.sql` добавляет `rr_client_orders`,
`rr_client_order_requests`, `rr_payment_receipts`, `rr_client_entitlements`.
Старые миграции 001–003 неизменны. Обычный автодеплой не применяет новую схему.

После полного успешного push CI для точного SHA загрузите
`scripts/upgrade-payments-vps.py` из этого же коммита, проверьте SHA-256
и запустите отдельным процессом от root:

```sh
python3 upgrade-payments-vps.py FULL_VERIFIED_COMMIT_SHA
```

Установщик принимает проверенный baseline
`fd557872d05659dad97b3ccd8cf969291c0f0e86`, сохраняет приватную контрольную
копию, применяет только дополнительную миграцию и обновляет контейнер API/Caddy.
После него проверяются прежний API, кабинет клиента, панель владельца,
отключённые платежи и восстановление 15 таблиц из закрытой резервной копии.
При сбое возвращается прежний образ и конфигурация; живая БД не затирается.

## Следующий отдельный шаг: включение только demo

Сначала подготовьте настройки в собственном кабинете Prodamus, не пересылая
секрет в чат или GitHub. Код поддерживает чтение секрета из приватного файла
внутри контейнера. Для него ещё требуется отдельное проверенное изменение
Compose с read-only монтированием и обновлением инфраструктурного baseline.
Одного добавления переменной на хосте недостаточно.

| Настройка приложения | Требование |
| --- | --- |
| `RR_PRODAMUS_MODE` | `demo`; значение `live` отклоняется при запуске |
| `RR_PRODAMUS_SECRET_FILE` | Путь к закрытому файлу внутри контейнера |
| `RR_PRODAMUS_FORM_URL` | Необязательно; допускается только `https://relationshipreset.payform.ru/` |
| `RR_PRODAMUS_SYS` | Необязательно, только выданный Prodamus идентификатор интеграции |

Не передавайте секрет через `RR_PRODAMUS_SECRET`: такой запуск отклоняется.
При отсутствии `sys` задайте в кабинете Prodamus общий адрес уведомлений:
`https://api-staging.poslessory.ru/payments/prodamus/webhook`.
Если уже есть рабочий получатель уведомлений, сначала согласуйте отдельную
тестовую настройку; его нельзя заменять молча. Передаваемый в ссылке
`urlNotification` используется кодом только при наличии `sys`.

Прежде чем включать demo, подтвердите в кабинете режим подписи и форму
уведомления. Текущая версия использует заданный секрет без автоматического
добавления `demo` и требует `demo_mode=1` в уведомлении. В документации описаны
разные варианты деморежима; несовпадение должно быть разобрано явно, а не
устранено отключением проверки подписи или признака demo.

Затем выполните один полный сценарий с вымышленной анкетой и тестовой оплатой
Prodamus: заказ → checkout → настоящий подписанный callback → один доступ →
повторный вход. Проверки CI с синтетически подписанными уведомлениями этого
сценария у провайдера не заменяют. Реальные списания не выполняются.

## Проверки и источники протокола

`ProdamusContractTest` проверяет парсинг форм и HMAC; `PaymentRoutesTest` —
авторизацию/CSRF/подпись и выключенный режим; `PaymentStoreIntegrationTest`
на одноразовом MySQL — владельца, повторы, гонки, удаление и атомарный откат.
`smoke-payments-vps.py` проверяет только выключенную конфигурацию и номер релиза.

Протокол сверялся с официальными разделами Prodamus:

- https://help.prodamus.ru/payform/tekhnicheskaya-dokumentaciya/sozdanie-platezhnoy-ssylki
- https://help.prodamus.ru/payform/tekhnicheskaya-dokumentaciya/webhook-ob-oplate
- https://help.prodamus.ru/payform/tekhnicheskaya-dokumentaciya/testirovanie-integracii

До публичного запуска остаются отдельными задачами: реальный режим платежей,
подтверждённая выдача услуги, возвраты, условия для клиента и проверка полного
сценария на рабочем домене. Этот релиз не заявляет их готовность.
