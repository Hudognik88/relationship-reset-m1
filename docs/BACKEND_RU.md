# Первый бэкенд Relationship Reset

Продолжение существующего проекта на Beget: PHP 8.3+ и MySQL. Это тестовый серверный этап. Публичная анкета пока работает локально в браузере; её ответы автоматически в БД не отправляются. Prodamus и внешняя генерация ИИ не подключены.

## Что реализовано

| Маршрут | Доступ | Назначение |
| --- | --- | --- |
| `GET /api/health.php` | Без токена | Проверить, что PHP отвечает; не подтверждает подключение БД |
| `GET /api/index.php?route=/ready` | Токен оператора | Проверить подключение к БД и установленную схему |
| `POST /api/index.php?route=/cases` | Токен оператора | Сохранить вымышленную анкету |
| `GET /api/index.php?route=/cases/{id}` | Токен оператора | Прочитать сохранённую анкету |
| `POST /api/index.php?route=/cases/{id}/drafts` | Токен оператора | Сохранить черновик ответа для последующей проверки человеком |

Токен передаётся только в заголовке `Authorization: Bearer …` по HTTPS. Не добавляйте его в адрес, клиентский JavaScript, скриншоты или GitHub. Публичного списка анкет нет. Отсутствующий или неверный конфиг закрывает доступ.

Точные форматы полей, создание токена в личном терминале, команды миграции и smoke-проверки описаны в [технической инструкции бэкенда](../backend/README_RU.md).

Запись анкеты требует `schema_version: "m1-cis-v1"`, `synthetic: true`, уникальный `client_request_id` и объект `questionnaire` с полями существующей анкеты. Это сознательно ограниченный тестовый API; наличие такого флага не заменяет обязанность оператора использовать только вымышленные данные. Реальные истории клиентов на этом этапе не принимаются.

Повторная отправка того же запроса с тем же идентификатором возвращает существующую запись. Повтор идентификатора с другим содержимым отклоняется. Черновик сохраняется как непроверенный: сам факт записи не означает одобрение, выдачу клиенту или оплату.

## Где находятся файлы

Публичные входы `api/index.php` и `api/health.php` лежат рядом с существующим сайтом. Код `backend/`, миграции и рабочий конфиг размещаются **за пределами `public_html`**. GitHub содержит только пустой образец конфигурации.

На хостинге используется структура:

- `<каталог сайта>/public_html/` — прежние шесть файлов сайта и `api/`;
- `<каталог сайта>/relationship-reset-private/releases/<commit>/backend/` — версия серверного кода;
- `<каталог сайта>/relationship-reset-private/current` — ссылка на активную версию;
- `<каталог сайта>/relationship-reset-private/shared/config.php` — настоящий конфиг, который не заменяется при деплое.

В проверенной панели Beget доступен MySQL 8.4; для сайта адрес БД — `localhost`, имя пользователя совпадает с именем базы. На момент подготовки база ещё не создана. Создайте отдельную тестовую БД и задайте её пароль непосредственно в Beget. Не включайте внешний доступ к БД ради сайта или GitHub Actions.

Скопируйте `backend/config.example.php` в приватный `shared/config.php`, заполните параметры БД и SHA-256 случайного операторского токена. Установите права на конфиг `600`. Сам токен храните отдельно в менеджере паролей. Не используйте пароль аккаунта Beget в качестве пароля БД или токена.

## Порядок включения

1. Подготовить загрузку по [инструкции автодеплоя](BEGET_AUTODEPLOY_RU.md).
2. Создать отдельную БД и приватный конфиг на Beget.
3. Выполнить миграцию через CLI PHP 8.3+; не открывать миграцию через URL. Автодеплой не изменяет схему БД.
4. Проверить `/health.php`, затем авторизованный `/ready` по HTTPS.
5. Прогнать вымышленный случай: запись → чтение → повтор без дубля → сохранение черновика. Проверить отказ без токена.

Выбор PHP для сайта и PHP в терминале Beget проверяется отдельно. Успешный локальный тест или CI не подтверждает состояние хостинга; завершённым подключение считается после проверок на Beget.

## Следующий небольшой этап

После работающего тестового API — согласовать приём и удаление реальных анкет, добавить понятное согласие и защищённый клиентский доступ, затем связать заказ с подтверждённой оплатой. Не превращать текущий операторский токен в публичный способ входа клиентов.
