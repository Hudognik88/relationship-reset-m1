# Публикация страницы интереса через CI

Страница `pilot.html` — отдельная витрина планируемого пилота за 990 ₽. На ней
нет форм, платежей, анкет, аналитики или обращения к API. Кнопка открывает
черновик письма в почтовом приложении посетителя; отправку выполняет сам посетитель.

**Статус этой подготовки:** код доставки реализован, но расширение приёмника на
Beget ещё не установлено. Страница ещё не опубликована. Артефакт CI сам по себе
не подтверждает публикацию; её подтверждает успешный job `publish` с проверкой HTTPS.

## Что делает CI

Workflow `pilot-page.yml` проверяет ограничения страницы и обновления приёмника,
затем собирает `pilot-interest-review.zip`. В архиве только `pilot.html` и манифест,
привязанный к полному SHA коммита и SHA256 содержимого.

Публикация доступна только из `m1-first-payment-20260925`, вне pull request,
при repository variable `BEGET_PILOT_DEPLOY_ENABLED=true`. Используется прежний
Environment `beget-staging` с его ограничением ветки и прежние SSH secrets.
Из feature-ветки и PR выполняются только проверки и сборка. Переменная должна
оставаться выключенной до установки расширения приёмника.

Доставка заменяет только `public_html/pilot.html` через временный файл и атомарное
переименование. Предыдущая версия и её права сохраняются в приватной резервной
копии. Сохраняются строгая проверка SSH host key и ограниченный ключ без shell.
После доставки CI проверяет код 200 и точный SHA256 по
`https://poslessory.ru/pilot.html`. Если эта проверка не прошла, публикация уже могла
состояться: сначала проверить страницу, не считать job успешным и не переключать
оплату. Автоматического отката по сетевой ошибке проверки нет.

Основной `index.html`, PHP/API, приватная конфигурация, БД и Kotlin не входят в эту
доставку. Общая группа concurrency и блокировка приёмника предотвращают одновременную
запись с прежним staging-деплоем.
Если при нескольких быстрых push один запуск отмечен `cancelled`, повторить
проверки последнего коммита: общая группа не является очередью всех запусков.

## Почему нужна однократная настройка на Beget

Установленный `deploy_beget_remote.py` принимает только восемь прежних публичных
файлов и пакет `mode=staging`; HTML обязан содержать тестовые маркеры. Нового
`pilot.html` в списке нет. Ограниченный CI-ключ не может обновлять собственный приёмник.

Подготовлен отдельный протокол `rr-publish-pilot SHA SHA256`. Он принимает ZIP
до 256 КиБ, HTML до 128 КиБ и ровно два ожидаемых файла; проверяет манифест,
контрольные суммы, отсутствие симлинков, скриптов, форм, загрузки внешних ресурсов
и посторонних ссылок. Разрешены навигация по странице, заданные email и Telegram.
Старый staging-протокол сохранён без изменения поведения.

`upgrade_pilot_receiver.py` — однократный шаг администратора. Он добавляет
`publish_pilot_remote.py` и небольшой диспетчер в существующий приёмник, сверяет
исходную версию с известным хешем и сохраняет резервную копию. При неизвестной
версии или симлинках останавливается. SSH-настройки, ключи и `authorized_keys`
не меняются. Сайт этот шаг не публикует.

## Порядок включения

1. Дождаться успешных проверок PR и проверить изменения. Использовать полный SHA
   проверенного коммита, содержащего три файла из следующего пункта.
2. Один раз запустить обновление приёмника в терминале **виртуального хостинга**
   под `movereed` (не в root-консоли VPS). Пример команды ниже запрашивает SHA;
   никаких паролей, токенов или ключей она не выводит.
3. Влить проверенный PR в `m1-first-payment-20260925`. Сохранить действующие
   ограничения Environment, не разрешать feature-ветке доступ к секретам.
4. В Settings → Secrets and variables → Actions → Variables добавить
   **repository variable** `BEGET_PILOT_DEPLOY_ENABLED` со значением `true`.
   Уровень repository нужен для условия job; environment variable для этого
   переключателя не подходит. Затем повторить CI `Pilot interest page` на
   проверенном коммите разрешённой ветки. Последующие изменения доставляются CI.
5. После зелёного `publish` открыть фактический адрес, проверить мобильный и
   настольный вид, раскрытие FAQ и почтовую кнопку. Только после этого давать
   адрес в публикациях. Основная страница пока остаётся тестовой.

```bash
(
  set -eu
  cd "$HOME/movereed.beget.tech"
  umask 077
  read -r -p 'Полный SHA проверенного коммита: ' rr_release
  [[ "$rr_release" =~ ^[0-9a-f]{40}$ ]] || exit 2
  rr_setup=$(mktemp -d "$PWD/setup-pilot.XXXXXX")
  for rr_file in upgrade_pilot_receiver.py publish_pilot_remote.py deploy_beget_remote.py
  do
    curl --fail --silent --show-error --location \
      --connect-timeout 15 --max-time 60 \
      "https://raw.githubusercontent.com/Hudognik88/relationship-reset-m1/$rr_release/scripts/$rr_file" \
      --output "$rr_setup/$rr_file"
  done
  python3 "$rr_setup/upgrade_pilot_receiver.py" "$(pwd -P)"
)
```

Это документированный следующий шаг, **не выполненная команда**. Пакет и
подготовка не означают готовность принимать реальные анкеты или платежи.
