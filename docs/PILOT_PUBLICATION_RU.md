# Автоматическая публикация пилота

## Текущая схема

Изменения сайта поступают в `m1-first-payment-20260925` через GitHub. Workflow
`Validate and deploy Beget staging` проверяет код и оба архива, затем одним job
последовательно доставляет прежнюю тестовую версию и публичный `pilot.html`.
Последний шаг сверяет код HTTP 200 и точный SHA256 опубликованной страницы по
`https://poslessory.ru/pilot.html`. Зелёный `validate` отдельно не подтверждает
публикацию: нужен зелёный `deploy`, включая шаг проверки пилота.

Применяются существующие Environment `beget-staging`, ограниченный SSH-ключ,
проверка SSH host key и repository variable `BEGET_DEPLOY_ENABLED=true`.
Новая переменная не требуется. В pull request и других ветках выполняются проверки;
секреты доставки доступны только прежней разрешённой ветке вне PR.

`pilot-page.yml` отдельно проверяет страницу и сохраняет артефакт
`pilot-interest-review.zip`; ничего не публикует. У него собственная группа
concurrency. За запись на хостинг отвечает один workflow, поэтому два разных
workflow не отменяют ожидающую публикацию друг друга и не конкурируют за блокировку.
В серии быстрых push промежуточный ожидающий запуск может быть заменён последним;
результат проверяем по SHA последнего коммита.

## Обычное обновление — без входа в Beget

1. Изменить `pilot.html` или прежние файлы сайта в GitHub и открыть PR в
   `m1-first-payment-20260925`.
2. Дождаться успешных проверок, проверить изменения и влить PR.
3. На коммите разрешённой ветки дождаться зелёного `deploy`. Он сам собирает
   архивы именно этого SHA, доставляет их и проверяет HTTPS.
4. Если проверка красная, прочитать соответствующий шаг в Actions. Не считать
   страницу опубликованной только по факту merge. Исправления также идут через CI.

Для отмены обычного изменения сделать revert через GitHub: это новый проверяемый
коммит, который доставляется тем же процессом. Старая версия `pilot.html` также
сохраняется приватно на хостинге. Сетевая ошибка итоговой HTTPS-проверки не запускает
автоматический откат: страница уже могла быть записана, поэтому сначала проверить
причину. БД и настройки Prodamus не входят в публикацию страницы.

## Что было сделано однократно

29 сентября 2026 года, Москва: в существующем терминале виртуального хостинга под
`movereed` установлен приёмник из проверенного коммита
`36894ada0253b4a49556dad823c6098498aa8eca`.

Исходный SHA256 `deploy_beget_remote.py` совпал с ожидаемым:
`f9579530f7650576c9a67ddc3cf43df03d656ed90850888925af9c0034f64569`.
Установщик вернул `status=upgraded`; резервная копия —
`relationship-reset-private/receiver-upgrade-backups/pilot-6aj9rw_r`.

Добавлен `publish_pilot_remote.py` и диспетчер отдельной команды
`rr-publish-pilot SHA SHA256` в прежний приёмник. SSH-настройки, ключи и
`authorized_keys` не менялись. Эта установка сама страницу не публиковала;
первая публикация должна пройти через CI после включения шага в workflow.

## Границы доставки

Архив пилота содержит только `pilot.html` и манифест с SHA коммита и SHA256
содержимого. Приёмник ограничивает ZIP 256 КиБ и HTML 128 КиБ; отвергает посторонние
файлы, симлинки, скрипты, формы, внешние ресурсы и посторонние ссылки. Замена страницы
атомарная, с резервной копией. Разрешены навигация, заданные email и Telegram.

Обычные изменения в этих пределах автоматические. Появление новых исполняемых
компонентов, изменение инфраструктуры или расширение прав — отдельное техническое
изменение, а не повод отключать проверки. Не обещать бессрочную автоматизацию
любых возможных изменений сервера.

Код Kotlin API и встроенные страницы кабинетов уже доставляются отдельным
существующим процессом из `kotlin-backend-20260926` после успешного push CI;
таймер проверяет обновления примерно каждые пять минут. Инфраструктура, зависимости
и миграции там закреплены отдельной проверенной версией. Этот этап Kotlin-код и
его инфраструктуру не меняет.

## Проверка готовой страницы

После зелёного `deploy` проверить фактический вид, раскрытие FAQ и ссылку на черновик
письма. Страница собирает только интерес к пилоту 990 ₽; оплата и приём личных
историй не открываются этим деплоем. Почтовая кнопка открывает приложение посетителя,
а не подключает почту к сервису и не отправляет письмо самостоятельно.
