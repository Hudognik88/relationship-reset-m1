# Первый бэкенд: только вымышленные репетиции

PHP 8.3+, PDO MySQL; MySQL 8.4 на Beget. Без Composer, Node-процесса и очереди.
Сайт и бесплатная анкета продолжают работать локально в браузере: они не отправляют ответы в этот API.
Оплата, публичный приём анкет, генерация ИИ и отправка клиентам не подключены.
Нет настройки, включающей реальные анкеты: POST требует `synthetic: true`; оператор должен передавать только полностью вымышленные примеры. Эта отметка не способна автоматически распознать реальные сведения в тексте.

## Раскладка на Beget

```
<site>/public_html/api/index.php
<site>/public_html/api/health.php
<site>/relationship-reset-private/current -> releases/<commit-sha>
<site>/relationship-reset-private/releases/<commit-sha>/backend/...
<site>/relationship-reset-private/shared/config.php
```

`backend` и действующий `config.php` не должны лежать в `public_html`.
Публичная точка входа загружает только фиксированный путь `../relationship-reset-private/current/backend/bootstrap.php` относительно `public_html`.
Внутренний config определяется через реальный путь выпуска. Для CLI/тестов можно задать `RR_CONFIG_FILE` абсолютным путём.
Веб-серверу необходим PHP 8.3 с `pdo_mysql`; HTTPS обязателен. Передачу заголовка `Authorization` от веб-сервера в PHP необходимо проверить на Beget: локальный встроенный сервер PHP этого не подтверждает. Smoke-проверка ниже требует анонимный отказ `401` и успешный авторизованный запрос. Не передавайте токен в URL.

## Первый запуск

1. В Beget создать отдельную базу MySQL. У Beget имя пользователя совпадает с именем базы; для сайта использовать `localhost`.
2. Скопировать `backend/config.example.php` в закрытый `shared/config.php`, заполнить БД и хеш токена. Права каталога `700`, файла `600`. Не загружать этот файл в GitHub и не присылать пароль в чат.
3. Создать случайный bearer-токен (не короче 32 случайных байт), хранить исходное значение в менеджере паролей; в config записать только SHA-256. Следующая CLI-команда печатает новый токен и его хеш **только для владельца в локальном терминале**. Не запускать её в публичном CI-журнале:

```sh
php -r '$t=rtrim(strtr(base64_encode(random_bytes(32)), "+/", "-_"), "="); echo "Token: ".$t.PHP_EOL."SHA256: ".hash("sha256",$t).PHP_EOL;'
```

4. В приватном выпуске выполнить миграцию. Указывать реальный путь и установленный на хостинге PHP CLI:

```sh
RR_CONFIG_FILE=/absolute/site/relationship-reset-private/shared/config.php php backend/bin/migrate.php
```

Миграция создаёт `rr_schema_migrations`, `rr_cases`, `rr_drafts`, не удаляет данные и проверяет контрольную сумму уже применённого SQL. Повторный запуск безопасен. Для следующих изменений создавайте новую миграцию, не редактируйте применённую.

5. После HTTPS сделать read-only smoke. Передать `RR_OPERATOR_TOKEN` через секретное окружение; не вставлять реальное значение в историю команд или URL:

```sh
php backend/bin/smoke.php https://poslessory.ru/api
```

Без config API закрыт с `503 service_unavailable`; liveness при этом доступен. При установленном config анонимный запрос получает `401` до обращения к БД. Readiness требует существующих таблиц и совпадающей миграции. Ответы не раскрывают реквизиты БД, SQL и пути.

## Операторский API

Все запросы, кроме health: `Authorization: Bearer <token>`. POST также `Content-Type: application/json`.
Нет CORS, публичных ключей, сессий и автодоставки. Токен нельзя помещать в HTML, JavaScript сайта, браузерное хранилище или frontend-переменные сборки.

| Метод и путь | Результат |
| --- | --- |
| GET `/api/health.php` | Liveness: `status=ok`, `mode=staging`; опциональный SHA выпуска, без проверки БД |
| GET `/api/index.php?route=/ready` | Аутентифицированная проверка БД и миграции |
| POST `/api/index.php?route=/cases` | Создать вымышленный кейс, `201`; идентичный повтор `200`; изменённый повтор с тем же ключом `409` |
| GET `/api/index.php?route=/cases/<id>` | Получить вымышленную анкету по случайному 32-символьному hex ID |
| POST `/api/index.php?route=/cases/<id>/drafts` | Сохранить вымышленный черновик с `reviewed=false`; без отправки клиенту |

Для кейса обязательны ровно `schema_version: "m1-cis-v1"`, `synthetic: true`, `client_request_id` (UUID v4 в нижнем регистре) и `questionnaire`. В questionnaire — все 11 enum-полей `app.js` и три строки: `situation` (1–2000 UTF-16 единиц), `success` (0–1000), `failure` (0–1000). Неизвестные поля, значения enum, невалидный UTF-8 и управляющие символы отклоняются. Пустые необязательные строки передавать как `""`.

Черновик: ровно `synthetic: true`, `client_request_id` и `text` (1–4000 UTF-16 единиц). Поля `reviewed`, получатель и отметки оплаты передавать нельзя. Повтор с тем же ключом учитывает и ID кейса: другой кейс возвращает `409`.

Лимит HTTP-тела — 16 KiB. Хеш идемпотентности считается по нормализованным полям в фиксированном порядке. Уникальные индексы БД разрешают одновременные повторы без дубликатов. Ключи кейсов и черновиков имеют отдельные пространства.

## Локальные проверки

```sh
php tests/backend-unit.php
php tests/backend-integration.php
```

Интеграционный тест требует `RR_CONFIG_FILE`, `RR_OPERATOR_TOKEN` и **отдельную тестовую БД**, поднимает PHP сервер только на loopback, применяет миграцию дважды, выполняет реальные HTTP/PDO-запросы с вымышленным примером и удаляет созданные им кейсы. `RR_LOCAL_TEST=1` разрешает HTTP только для PHP встроенного сервера и loopback-клиента; в обычном хостинге флаг не отключает HTTPS.

До реальных клиентов потребуется отдельное изменение: выбранный разрешённый ИИ-провайдер, согласованный канал выдачи, политика хранения/удаления, контроль доступа оператора и подтверждённый платёжный сценарий. В этой версии нет флага для обхода этого этапа.
